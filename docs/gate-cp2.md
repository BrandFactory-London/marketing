## Migrations

### Backlog item 6: the transactional route (γ2.0)

- `scripts/migrate-lib.ts`: Neon targets now use `drizzle-orm/neon-serverless` with `@neondatabase/serverless`'s `Client` over WebSocket (port 443). Drizzle's Postgres migrator (`pg-core/dialect.js`, `migrate()`) runs every pending migration inside one `session.transaction`, so a failure part-way rolls back the whole run. The `neon-http` path is removed. Local and other hosts keep node-postgres, also in one transaction.
- New `--rehearse <tag>`: runs one migration's SQL inside `BEGIN ... ROLLBACK`, prints the tables seen inside the transaction, rolls back, then prints the normal check. It never writes the migrations table.
- The independent check now copes with a database that has no `drizzle` schema yet.
- **Tests** (`scripts/migrate.test.ts`, 11): the real Neon driver and the real Drizzle migrator run through a local WebSocket-to-TCP relay to a scratch database. They cover:
  - the repo's migrations apply, and a second run is a no-op;
  - a counter shows the traffic went through the relay;
  - **two pending migrations where the second fails part-way leave no tables and no migration row**;
  - a failing run after an earlier applied migration keeps the earlier one and rolls back only the failing run;
  - the rehearsal leaves the database unchanged;
  - `--check-only` runs no migration.
- **Read-only check on the Neon dev branch** over the new driver (21 Oct 2026, output verbatim):
